1. ALGORITHME DE FORMATAGE (PRIORITÉ ABSOLUE)

Pour chaque ligne, tu dois appliquer strictement cette logique avant de traduire :

* CAS A : La ligne commence par ; suivi DIRECTEMENT d'un code hexa (ex: ;8D4C...)
    -> ACTION : SUPPRIMER le ; initial.
    -> Résultat attendu : 8D4C...=Traduction Albanais

* CAS B : La ligne commence par ;^ suivi d'un code hexa (ex: ;^BEE3...)
    -> ACTION : CONSERVER le ; intact.
    -> Résultat attendu : ;^BEE3...=Traduction Albanais

* CAS C : La ligne commence par [ ou ne contient pas de =
    -> ACTION : Recopier la ligne à l'identique sans aucune modification.

2. RÈGLES DE STRUCTURE (SÉQUENCE STRICTE)

L'ordre des caractères générés est une priorité absolue. Tu ne dois pas te laisser perturber par l'affichage RTL (Right-to-Left) du farsi. Chaque ligne traduite doit SUIVRE EXACTEMENT CETTE SÉQUENCE DE CARACTÈRES, dans cet ordre précis :

[ÉTAPE 1] : Le code hexadécimal d'origine (ex: 2E78C36A41ED5549 ou ;^BEE3...)
[ÉTAPE 2] : Le signe égal (=) sans aucun espace avant ni après.
[ÉTAPE 3] : La traduction en farsi.

MODÈLE OBLIGATOIRE : [CODE_HEXA]=[TRADUCTION_FARSIE]

Exemple de séquence mentale que tu dois produire :
Texte source : F879FCB438A12D55=Default: all effect parameter sections open
Ta génération : F879FCB438A12D55=پیش‌فرض: تمام زیربخش‌های پارامتر افکت باز باشند

PRÉSERVATION : Ne change jamais l'ordre des lignes, les espaces de début de ligne, ou les balises de contrôle (\t, \n, %s, %d, etc.). Ne garde jamais l'anglais d'origine dans la traduction finale.
SORTIE : Réponds UNIQUEMENT sous forme de bloc de code Markdown (```text) pour forcer l'affichage brut de gauche à droite et éviter les bugs de rendu bidirectionnel.
